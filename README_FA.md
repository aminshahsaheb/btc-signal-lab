# آزمایشگاه پژوهش بیت‌کوین — BTC Signal Lab

**یک فضای پژوهشی خصوصی و قابل ممیزی برای زمان‌بندی حرکت بیت‌کوین، آزمون فرضیه‌های جهت، کنترل ریسک و اعتبارسنجی رو‌به‌جلو.**

> **وضعیت در ۳۰ اکتبر ۲۰۲۶:** هیچ استراتژی این مخزن سودآور یا مستقل از داده‌ی کشف‌شده تأیید نشده است. پیش‌ثبت D-LIQ r1 هنوز قفل نشده؛ collector زنده وجود ندارد، داده‌ی زنده‌ای برای آن امتیازدهی نشده و T0 تعیین نشده است. پنل Move-Odds v0.1.2 و Risk-First Helper v0.3.1 نیز در محیط حاضر با کامپایلر واقعی TradingView کامپایل نشده‌اند.

## چرا مخزن جدا لازم است؟

اکنون پروژه چند بخش مستقل دارد که باید نسخه، مستندات و شواهد هرکدام جدا ثبت شود. این مخزن از پروژه‌های Fanus جداست و اجازه نمی‌دهد یک پنل، یک فرضیه یا یک ماشین‌حساب ریسک به‌اشتباه «استراتژی تأییدشده» معرفی شود.

| بخش | پرسش | وضعیت | چه چیزی را ثابت نمی‌کند؟ |
|---|---|---|---|
| Move-Odds | چه زمانی حرکت بزرگ محتمل‌تر است؟ | ابزار تاریخی؛ بسته‌ی Pine v0.1.2 موجود است | جهت یا سودآوری |
| D-LIQ | آیا جهت snapshotهای لیکوییدیشن، ادامه‌ی حرکت چهار ساعته را پیش‌بینی می‌کند؟ | پیش‌ثبت r1؛ قفل نشده | وجود سیگنال Long/Short معتبر |
| Risk-First | آیا طرح معامله از چک‌های ریسکِ تنظیم‌شده عبور می‌کند؟ | چک‌لیست دستی Pine | مزیت جهت‌دار یا اجرای خودکار |
| اعتبارسنجی اجرا | آیا سیگنال پس از کارمزد، اسپرد، لغزش، funding و تفاوت venue قابل معامله است؟ | شروع نشده | سودآوری روی KCEX |

این بخش‌ها با هم ترکیب نمی‌شوند. پیش از ساخت هر سیگنال ترکیبی، هر جزء باید مستقل از آزمون خود عبور کند و ترکیب باید پیش‌ثبت تازه داشته باشد.

## از کجا شروع کنی؟

1. [`docs/STATUS.md`](docs/STATUS.md) را برای وضعیت و موانع فعلی بخوان.
2. [`docs/PROJECT_MAP.md`](docs/PROJECT_MAP.md) را برای مرز و نقش هر بخش بخوان.
3. پیش از هر تغییر، [`docs/RESEARCH_RULES.md`](docs/RESEARCH_RULES.md) را رعایت کن.
4. آخرین بازبینی مستقل در [`docs/reviews/2026-10-30-dliq-r1-move-odds-review.md`](docs/reviews/2026-10-30-dliq-r1-move-odds-review.md) است.
5. یکپارچگی فایل‌ها را بررسی کن:

   ```bash
   python3 scripts/verify_sources.py
   ```

6. برای Move-Odds، فایل [`tools/move-odds-panel/v0.1.2/README_FA.md`](tools/move-odds-panel/v0.1.2/README_FA.md) را بخوان و ۱۲ بردار طلایی را در TradingView بررسی کن. گزارش ایستا جایگزین کامپایل واقعی Pine نیست. همچنین بازبینی [`docs/reviews/2026-10-30-move-odds-package-portability.md`](docs/reviews/2026-10-30-move-odds-package-portability.md) نشان می‌دهد بعضی اسکریپت‌های بررسی به پوشه‌ی خارجی `../atlas/` وابسته‌اند و یک اسکریپت هنوز نام فایل v0.1.1 را دارد؛ پس خروجی‌های قدیمی حفظ شده‌اند، اما harness هنوز از clone تمیز مستقل و آماده‌ی اجرا نیست.

## فهرست کامل منابع و نسخه‌های قبلی

گزارش [`docs/PROJECT_AUDIT_2026-10-30.md`](docs/PROJECT_AUDIT_2026-10-30.md) مشخص می‌کند هر فایل از کجا آمده، کجا نگه‌داری می‌شود و چرا بعضی موارد عمداً وارد Git نشده‌اند. PDF فارسی اطلس، بسته‌ی کامل Atlas، نسخه‌های قدیمی Move-Odds از v0.1 تا v0.1.2، نسخه‌های r5/r6/r7 ژورنال و بازبینی‌های D-LIQ در مسیرهای جدا نگه‌داری می‌شوند.

**یک کمبود مهم:** فایل ورودی مستقل `pkg_data.csv` موردنیاز Atlas بازیابی شده و نسخه فشرده آن در مسیر `artifacts/data/BTCUSDT_5m_2021_to_latest_csv.gz` نگه‌داری می‌شود. هش فایل استخراج‌شده با پیشوند هش مورد انتظار در README بسته Atlas تطبیق دارد و ساختار داده نیز بررسی شده است. بازتولید تاریخی Atlas در محیط ایزوله انجام شده؛ بااین‌حال این موفقیت به معنی اعتبارسنجی مستقل یک مزیت معاملاتی یا وجود شواهد تازه نیست.

فایل خام گفت‌وگو عمداً به Git اضافه نشده است؛ این فایل مرجع پژوهشی تمیز نیست و ممکن است اطلاعات شخصی یا نامرتبط داشته باشد. تصمیم‌ها و یافته‌های لازم در اسناد تاریخ‌دار و پاک‌سازی‌شده نگه‌داری می‌شوند.

## قوانین داده و شواهد

- داده‌ی تاریخی BTC از **۱ ژانویه‌ی ۲۰۲۱ تا ۲۲ سپتامبر ۲۰۲۶** برای کاوش‌های قبلی و انتخاب مدل استفاده شده است؛ برای ادعای تازه‌ی جهت، holdout پاک نیست.
- بسته‌ی Atlas فقط به‌عنوان آرشیو سابقه و منشأ نگه‌داری می‌شود؛ از آن برای نجات فرضیه‌ی شکست‌خورده، انتخاب threshold یا ادعای forward استفاده نکن.
- D-LIQ r1 هنوز باید روش آماری، اعتبار پیام، حذف تکرار، حساب نمونه و روش anchoring ژورنال را ببندد.
- probe احتمالی پیش از T0، در صورت مجاز شدن، فقط برای کیفیت feed است؛ بازده و رابطه‌ی ویژگی با قیمت در آن ممنوع است.
- کلید API، اطلاعات حساب، لاگ زنده، فایل کامل داده‌ی خام OHLC و خروجی خام مکالمه‌ی شخصی در این مخزن نیست. این موارد عمداً حذف شده‌اند یا در منابع در دسترس نبودند؛ نبودن فایل خام را نباید با کامل‌بودن داده اشتباه گرفت.

## وضعیت همگام‌سازی مخزن

**انتشار در ۳۰ اکتبر ۲۰۲۶ با بررسی مستقل تأیید شد.** شاخه‌ی `main` روی Commit زیر قرار دارد:

`1886f9e6b5e424bd6e421b28eded3b068ff25398`

درخت بازگشتی GitHub شامل ۱۱۲ فایل است. فهرست SHA-256 شامل ۱۱۱ ورودی است، زیرا خود فایل فهرست را درون خودش هش نمی‌کند. فایل داده‌ی فشرده‌ی BTCUSDT، آرشیو Atlas، خروجی‌های بازتولید، بسته‌های Move-Odds، مستندات پژوهش، کدهای Pine، اسکریپت‌ها و Workflow بررسی یکپارچگی در مخزن Remote حضور دارند.

Workflow با نام `verify-source-artifacts` برای همین Commit اجرا شد و موفق بود. این نتیجه فقط بررسی‌های یکپارچگی فایل را تأیید می‌کند؛ نه اعتبار فرضیه‌ی معاملاتی، کامپایل Pine، کیفیت داده‌ی زنده یا سودآوری اجرا را.

## وضعیت انتشار

مخزن باید در ابتدا **خصوصی** باشد. فایل مجوز اضافه نشده، چون شرایط انتشار و استفاده‌ی مجدد هنوز تعیین نشده‌اند. قبل از عمومی‌کردن، محتوای آرشیو، حق استفاده از داده و اطلاعاتی را که قرار است افشا شود بازبینی کن.

این مخزن پرونده‌ی پژوهش است، نه توصیه‌ی مالی و نه وعده‌ی بازده. هدف این است که رد یک فرضیه راحت‌تر از نجات آن با تنظیم‌های پس از مشاهده‌ی داده باشد.
