# Contributing and changing research artifacts

This is primarily an internal research repository. Changes to explanatory documentation are welcome, but changes to a hypothesis or analysis contract require stricter review.

## Before any research change

- State the specific question being changed.
- Link the prior decision or preregistration.
- Explain whether the change was decided before or after any outcome data was examined.
- Create a new versioned specification; do not silently edit a locked document.
- Record the data period, source, exclusions, analysis code hash, and multiplicity implications.
- Re-run integrity checks. Do not represent those checks as a scientific revalidation.

## Pull request checklist

- [ ] No secrets, personal exports, or raw live capture added.
- [ ] No already-inspected history presented as a clean holdout.
- [ ] No feature, direction, threshold, or horizon changed after outcome inspection without a new preregistration.
- [ ] Draft/locked status is accurate.
- [ ] Source hashes and tests were updated only when justified.
- [ ] Claims match the checks actually run.
