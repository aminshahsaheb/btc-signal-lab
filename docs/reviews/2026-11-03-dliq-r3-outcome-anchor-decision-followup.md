# D-LIQ r3.1 Builder — outcome-anchor decision follow-up

Date: 2026-11-03  
PR: #15  
Decision: `DLIQ-DEC-2026-11-03-OUTCOME-ANCHOR-01`

## Disposition

The owner approved the strict project rule: a row may enter `slots.csv` only after a valid later CHECKPOINT covers the OUTCOME event itself. A checkpoint that covers only the SLOT is not enough.

The Builder already implements this rule. It uses the monotonic checkpoint-covered sequence, rejects impossible or regressing checkpoint coverage, and leaves an otherwise valid row as `PENDING` when the OUTCOME is outside the covered prefix. Any PENDING row blocks analysis CSV output. The immutable r3.1 protocol file and its source archive were not changed.

## Actual-verifier integration

Two immutable synthetic fixtures are added. Their verifier reports were generated by the exact writer, primary verifier, and independent verifier from the supplied candidate archive. Source hashes are recorded in the integration test.

- Positive: both actual verifiers PASS; a later checkpoint covers the OUTCOME; the Builder emits one EVAL row.
- Negative: both actual verifiers PASS and report `TAIL_UNANCHORED`; the SLOT is covered but the OUTCOME is not; the Builder leaves the row PENDING and emits no analysis row.

The fixtures use a local MockAnchor. They prove Builder compatibility with these actual verifier report shapes and the strict tail policy for these synthetic cases. They do not prove a real anchor, live feed, collector, protocol lock, or market edge.

## Remaining gates

- Exact-head CI must pass, including actual-verifier integration and full repository inventory.
- Independent third-party code and protocol review is still required.
- Replay-based `SLOT_MISMATCH` differential coverage remains open.
- OPEN-17, OPEN-18, OPEN-21 and other dated protocol decisions remain separate.
- No live exchange, external anchor, collector, T0, or strategy scoring is authorized.
